# 多因素资格实验 SSOT

> Auth/Checkout/Billing/Runner 多阶段出口与调度编排统一见 [试用资格与多支付提链 SSOT](../trial-payment-probe/README.md)。本文件保留实验设计细节。

## 目标

在持续发现试用资格链接的同时，区分账号、国家、实际出口 IP/ASN、三阶段路由、支付方式、seed、时间和执行顺序的影响。所有结论以逐次观测、平衡覆盖和证据门为准，国家排行榜仅用于调度，不直接等同因果结论。

## 唯一流程

1. 健康门：先剔除失败或冷却中的国家出口与 seed。
2. 设计门：根据 `discovery / attribution / hybrid` 生成带实验臂的排程。
3. 执行门：按排程覆盖 Auth/Checkout/Billing 路由、支付方式和 seed 序号。
4. 观测门：每次请求保存计划值、实际三阶段国家/IP/ASN、结果、价格、方式、时间与顺序。
5. 证据门：Wilson 区间、匹配分层、混杂审计、重复稳定性和漂移检测共同决定结论等级。
6. 产出门：命中链接入库；实验数据支持 JSON/CSV 导出和再次导入。

## 三种模式

- `discovery`：优先高命中国家，保留未知国家探索；命中后可提前结束该账号本轮。
- `attribution`：补齐账号×国家矩阵，命中后继续；路由、支付方式和 seed 按正交顺序轮换。
- `hybrid`：默认 50% 利用、30% 平衡、20% 探索，在同一轮内同时维持产出和证据积累。

## 路由语法

每行一个变体：`名称=Auth>Checkout>Billing`。`@` 表示当前探测国家，例如：

```text
same=@>@>@
split=@>VN>@
independent=US>JP>DE
```

运行时分别映射到 UPL 的 bootstrap、promotion、provider 网络阶段；观测同时保存计划路由和实际出口证据。

## 结论边界

- 同账号跨出口、同出口跨账号、跨时段重复未达门槛时，账号/国家/IP/随机四类解释均保持“证据不足”。
- 计划国家与实际 Checkout 出口验证覆盖低于 80% 时，只输出探索线索。
- 每个 IP/ASN 至少 10 次且覆盖至少 2 个账号后，才评估具体出口效应。
- 支付方式只从已探测支持集合中自动选择；无支持证据时使用 `auto` 并单独标记。

## 0.0.31 自适应归因协议

### 运行前门禁

设置页必须在零观测时也给出实验可识别性，分别检查有效账号、健康实际国家、实际 IP、ASN、路由变体、已支持支付方式和跨时段重复。某因素缺少至少两个水平，或没有同一匹配层内的交叉样本时，该因素保持“阻塞/采集中”，不得由国家排行榜替代因果结论。

### 观测变量

每条账号×出口观测除既有结果外，还记录：token 年龄与剩余期、邮箱域、账号批次、浏览器配置档、设备分组、locale/timezone 与出口一致性、Checkout 网段与网络类型、活动/产品/模式、重试序号、冷却时长、Checkout 结构指纹、优惠集合指纹、上游协议指纹和规则纪元。导出仍不包含 access token。

### 规则纪元与漂移

1. 新观测根据响应结构、执行管线、产品和 Runner 协议生成稳定指纹。
2. 指纹改变后创建新规则纪元，当前推荐和因素报告只使用最新纪元。
3. Checkout 结构或优惠集合发生持续替换时生成漂移告警。
4. 普通规则漂移将探索比例提高到至少 35%，严重漂移提高到 50%；从利用流量中等量扣减。
5. 旧纪元保留用于历史对比和导出，不参与当前国家/方式优先级。

### 当前真实环境结论（2026-07-30）

- Register-Tool 有 82 个 JWT `exp` 未过期 session；真实抽样 8 个后，仅 1 个仍被 Checkout 接受，7 个已被上游撤销，因此必须以真实 401 复核而不是本地过期时间判断可用性。
- Mullvad 真实扩展存储有 485 个邮箱记录，但没有 access token 和历史 Probe Observation。
- 历史批次中本地 `127.0.0.1:10808` 前置出口曾动态变化，最终批次健康检查实际国家为 CA，早期检查曾出现 HK。
- 2026-08-09 只读复测时 `10808` 为单一 SG 出口，Cloudflare 与 ChatGPT trace 均为 HTTP 200；`7890` 未监听，TH/IN/JP/US 多国家链式出口凭据未注入，因此仍没有多个健康实际国家。
- 2026-08-10 使用 v2rayN 自动生成的 72 节点测试配置完成只读矩阵复测：55 个端口成功访问 ChatGPT trace，去重为 27 个实际出口并覆盖 JP/SG/US/TW；JP/SG/US 三个代表端口已形成 Auth/Checkout/Billing 单轮互异出口证据。该配置尚未成为持久续租来源，且缺少有效身份，因此仍未进入跨时段平衡单元。
- 最终真实批次完成 8/8 单元：7 个 `account-auth` error、1 个严格资格 miss、0 个命中、0 个链接入库。唯一有效账号可创建普通 Checkout 并完成 promotion update，但 API 与页面均未确认零元/试用。
- 当前仅有 1 个真实可用账号，账号、国家、具体出口 IP/ASN 与随机分配四类解释仍缺少可识别的平衡交叉证据。
